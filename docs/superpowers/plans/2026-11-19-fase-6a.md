# Fase 6A — Visão ao vivo do atraso — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pôr a idade de cada parte do lote no Panorama ("Onde está" com idade, coluna "Parado há", faceta e coluna
"Complicação") e a seção "Onde está travando" na tela do Pedido, sem digitação nova.

**Architecture:** Um cálculo puro (`CalculoDaIdade`) pareia por ordem de chegada as linhas do livro de cada nó em cada
`Local` e devolve as partes vivas com data de chegada e as permanências dos passos já passados. Duas leituras o usam: o
`GET /panorama`, que ganha datas e complicações, e a rota nova `GET /pedidos/{id}/andamento`. O servidor manda datas e
o `agora` dele; o cliente formata a idade.

**Tech Stack:** .NET (C#), ASP.NET Core, EF Core Database First, SQL Server, xUnit; React + TypeScript (Vite), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-fase-6a-visao-ao-vivo-design.md` (aprovada em 2026-11-19). As referências
D*/C* deste plano são as da spec.

## Global Constraints

- Nomes de domínio em português, técnicos em inglês (`CLAUDE.md`, «Convenções de nomenclatura»).
- **Sem mudança de schema** (C15): nenhum `alter`, nada em `specs/02-modelo-de-dados.sql`.
- **Tempo de calendário** (C1); a pausa não se desconta da idade.
- **O servidor manda datas e `agora`** (C12); o cliente nunca usa `Date.now()` para a idade.
- **Cor** (C9): idade, "Parado há", complicações e "mais parado" são neutros (`text-tinta`, `text-tinta-fraca`, `Pilula`
  neutra, peso e borda); só "Atrasado" (`atraso`), "Pausado" (`atencao`) e a aferição mantêm tom.
- **Perfis** (C13): as duas leituras são `[Authorize]` sem `Roles`; nenhuma entrada nova em `permissoes.ts`.
- **Formato da idade** (C7): `< 1 h` → "há menos de 1 h"; `< 24 h` → "há N h"; senão "há N d", dias inteiros
  arredondados para baixo.
- **Complicações** (C8), códigos estáveis e ordem fixa: `MaterialPendente`, `AguardandoLiberacao`, `AguardandoDecisao`,
  `EmConserto`, `MontagemIncompleta`, `ARepor`.
- **Durações no JSON em segundos inteiros** (`long`), datas no formato que o `HorarioDeBrasiliaJsonConverter` já aplica.
- Ciclo de cada task: `dotnet build Rastreamento.slnx -warnaserror` (0 avisos) e `dotnet test Rastreamento.slnx -m:1`
  quando toca backend; `npm test -- --run --maxWorkers=2` **e** `npm run build` em `web/` quando toca front.
- Testes de tela: `// @vitest-environment jsdom`, `afterEach(cleanup)`, `web/src/testes/api.ts`; `data-testid` só pela
  regra do `CLAUDE.md`.
- Citação em comentário e prosa **pelo nome**, nunca `arquivo:NN` (`CLAUDE.md`, «Convenção de citação»).

## Review Focus

- **Peça com filhos só "a iniciar"**: o "Parado há" dela vem dos filhos, não do `Agrupamento.CriadoEm` (C5). Teste na Task 5.
- **Linhas com o mesmo `DataHora`** (o lote grava várias de uma vez): o desempate é o `Id`, e o resultado não depende da
  ordem em que a consulta devolve as linhas. Teste na Task 1.
- **Quantidades decimais** (lote em kg ou metro, `DECIMAL(18,4)`): a divisão de uma chegada não perde nem inventa
  fração. Teste na Task 1.
- **`agora` anterior ao `desde`** (relógio do banco e do app diferentes, ou cache): a idade nunca sai negativa; mostra
  "há menos de 1 h". Teste na Task 8.
- **Nó sem Roteiro** (vai direto à expedição ou à montagem): a trilha não quebra e mostra só os blocos que existem.
  Teste na Task 7.

**Interfaces:**
- Produces:
  - `public sealed record NoDaIdade(int Id, decimal Quantidade, DateTime CriadoEm)` — `CriadoEm` é o `Agrupamento.CriadoEm` do nó (C4).
  - `public sealed record ParteViva(int EstruturaItemId, Local Local, decimal Quantidade, DateTime Chegada)`
  - `public sealed record Permanencia(int EstruturaItemId, int SetorId, int Ordem, decimal Quantidade, TimeSpan Duracao)`
  - `public sealed class IdadesDoLivro` com:
    - `IReadOnlyList<ParteViva> Partes(int noId)` — as partes vivas do nó, em ordem de chegada;
    - `DateTime? MaisAntiga(int noId, Func<Local, bool> onde)` — a menor `Chegada` entre as partes do nó cujo `Local` satisfaz `onde`;
    - `TimeSpan? PermanenciaMedia(int noId, int ordem)` — média ponderada pela quantidade das `Permanencia` do passo; `null` sem nenhuma.
  - `public static class CalculoDaIdade { public static IdadesDoLivro Calcular(IReadOnlyCollection<NoDaIdade> nos, IReadOnlyList<Movimentacao> linhas); }`

Algoritmo (o que a assinatura não determina): descartar toda linha `Tipo = Estorno` e toda linha cujo `Id` é o
`EstornoDeId` de alguma linha (C3); ordenar o resto por `DataHora`, depois `Id`; semear o `Local.AIniciar` de cada nó
com uma chegada implícita de `Quantidade` em `CriadoEm` (C4); para cada linha, a saída consome do `Local.DaOrigem(m)`
as chegadas mais antigas (dividindo a última), registrando `Permanencia` quando a origem é `NoSetor` e o `Tipo` é
`Termino`, e a chegada é empilhada em `Local.DoDestino(m)` com `m.DataHora`. `Montado`, `Expedido` e `Perdido` não
guardam partes (C5). Saída maior que as chegadas vivas consome o que houver e não lança (seção 3.1).
