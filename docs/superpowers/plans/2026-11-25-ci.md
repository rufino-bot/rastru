# CI (parte 1 do CI/CD) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Todo PR para a `main` e todo push na `main` rodam o build e as suítes do backend (contra SQL Server real) e do front, com o resultado no PR.

**Architecture:** Um workflow `.github/workflows/ci.yml` com dois jobs paralelos em runner hospedado do GitHub. O banco de teste é preparado pelo **mesmo** script que as sessões de nuvem usam — a parte de banco do `scripts/backend-na-nuvem` vira `scripts/banco-de-teste`, sem exigir root, e os dois caminhos passam a chamá-la. O workflow fica fino: chama o script e os comandos do `CLAUDE.md`.

**Tech Stack:** GitHub Actions (`ubuntu-24.04`), Docker Compose do runner, `actions/setup-dotnet` (.NET 10), `actions/setup-node` (Node 22), bash.

**Spec:** `docs/superpowers/specs/2026-11-25-ci-cd-design.md` — seções 4 (o CI), 8 (partição, parte 1) e D3/C22/C24.

## Global Constraints

- O banco do CI é **`Rastreamento`** em **`localhost:1433`**, `sa` / `Your_strong_Pass123`: a conexão está fixa em `TesteComBanco`, em `ArquivoDeComponenteRepositoryTests` e no `appsettings.json` da API (seção 4 da spec).
- Backend: `dotnet build Rastreamento.slnx -warnaserror` e `dotnet test Rastreamento.slnx -m:1` — o `-m:1` é obrigatório.
- Front, em `web/`: `npm ci`, `npm test -- --run --maxWorkers=2`, `npm run build`.
- Scripts SQL aplicados com `-b -f 65001` e copiados para dentro do container (acentuação dos `NVARCHAR`).
- Gatilhos: `pull_request` para `main` e `push` em `main` (C22). Nada de `pull_request_target`.
- Nenhum segredo no CI: a senha `sa` é a de dev, já pública, e o banco é descartável.
- Nomes de domínio e prosa em português; comentários citam pelo nome, nunca `arquivo:NN` (seção «Convenção de citação» do `CLAUDE.md`).

## Review Focus

1. **O SQL Server demora a aceitar conexão no runner** — o script espera (até ~2 min) e falha alto com mensagem, em vez de deixar o `dotnet test` estourar com erro de conexão. (Task 1, passo de espera.)
2. **Banco já existente com schema** (sessão de nuvem rodando o script pela segunda vez) — não reaplica schema nem seed, sai 0. (Task 1, segunda execução.)
3. **`backend-na-nuvem` continua fazendo o que fazia** para a sessão de nuvem: SDK, `dockerd`, banco — só que delegando o banco. (Task 1, execução completa.)
4. **Teste flaky ficando vermelho no CI** — a regra de registro (spec, seção 4) está escrita onde quem vê o vermelho lê: no `CLAUDE.md`. (Task 3.)
5. **Um PR de fork** não ganha permissão de escrita nem segredo: `permissions: contents: read` e gatilho `pull_request`. (Task 2, conferido no YAML.)

### Task 2: `.github/workflows/ci.yml`

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `scripts/banco-de-teste` (Task 1).
- Produces: workflow `CI` com os jobs **`backend`** e **`front`** — esses dois nomes são o que o usuário marca como check obrigatório (Task 3 os cita).

- [ ] **Step 1: Escrever o workflow** com:
  - `name: CI`; `on: pull_request: branches: [main]` e `push: branches: [main]`.
  - `permissions: contents: read` no topo.
  - `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`.
  - Job `backend` (`runs-on: ubuntu-24.04`, `timeout-minutes: 45`): checkout; `actions/setup-dotnet` com `dotnet-version: 10.0.x` e cache de NuGet; `bash scripts/banco-de-teste`; `dotnet build Rastreamento.slnx -warnaserror`; `dotnet test Rastreamento.slnx -m:1 --no-build --logger trx --results-directory TestResults`; `actions/upload-artifact` dos `TestResults/**/*.trx` com `if: always()`.
  - Job `front` (`runs-on: ubuntu-24.04`, `timeout-minutes: 20`, `defaults.run.working-directory: web`): checkout; `actions/setup-node` com `node-version: 22` e cache npm (`cache-dependency-path: web/package-lock.json`); `npm ci`; `npm test -- --run --maxWorkers=2`; `npm run build`.
  - Cada `uses:` com a **versão maior** atual da action (ex.: `actions/checkout@v4` ou a mais nova existente — conferir no marketplace na hora), comentada com o motivo de não fixar SHA: repositório de projeto, actions oficiais do GitHub.

Expected: nenhum erro.
